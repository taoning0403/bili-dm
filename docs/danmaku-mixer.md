# 哔哩哔哩弹幕混合

日期：2026-10-04。在当前内嵌 libmpv 播放器上增加独立的弹幕解析、画面匹配、区间混合与显示功能。

## 使用

1. 先打开本地视频或播放选中的磁力视频，等待播放器读取时长。
2. 打开右侧“混合弹幕”。可以按自动填入的标题搜索，也可以每行粘贴一个 BV / ep / ss、Bilibili 视频链接或 b23.tv 短链接后批量解析。不带 `?p=` 的投稿视频读取全部分 P，带该参数只读取指定分 P；会员来源可先扫码登录。
3. 选择“标准”或“兼容删减与重绘”策略，再搜索并逐一匹配，或智能匹配已经解析的弹幕源。也可以直接“手动添加区间”。同一源可以添加多个不连续区间，多个源可以覆盖同一目标区间，也可以拼接覆盖完整视频。
4. 用对照预览检查映射、拖动时间轴边界或编辑“源开始 / 源结束 / 当前开始 / 当前结束”。单位为秒、支持小数。可以定位目标开始位置、用当前播放进度设置目标起点或拆分区间；待确认结果需要勾选后才会参与混合。
5. 点击“生成混合文件并播放”。Rust 校验边界和时长；未经生成的编辑不会替换上次已应用的弹幕。
6. 可以开关弹幕、调整字号和透明度，或通过系统保存对话框导出标准 XML。重开同一视频自动读取本地已生成项目，不触发 B 站请求。

## 时间映射

区间为半开区间 `[sourceStart, sourceEnd)`，避免相邻截取区间重复纳入边界弹幕。映射公式：

```text
targetTime = targetStart + (sourceTime - sourceStart)
             × (targetEnd - targetStart) / (sourceEnd - sourceStart)
```

所有时间必须有限、非负且位于各自视频时长内。时长比例允许 0.25～4，非等时长显示同步提示。相同来源、相同弹幕 ID、相同映射毫秒的记录去重；不同来源/用户的相同文字仍保留。结果按目标时间排序，超出当前视频的弹幕不会输出；未覆盖的视频区间有明确提示。

## 解析与匹配

- `bilibili.rs` 读取 `view` 的 BV/CID/分 P/时长，按每 360 秒读取 `seg.so` protobuf 分段。分段失败使该弹幕源本次解析失败，不把半套弹幕标成成功；批次内其余源可以成功。每批 20 个输入，每项目 50 个分 P、20 万条弹幕，最长手动视频 24 小时。
- 视频流在匹配时取得，优先低带宽 AVC DASH；音画结合或仅音频模式会另取音频流。普通 playurl 失败时尝试 WBI 接口。拒绝明显不符的预览时长。CDN URL 不写入项目，使用应用本地扫码会话，不读取浏览器 Cookie。旧版多段 durl、直播尚不支持；番剧 ep/ss 使用独立剧集元数据和播放鉴权。
- 独立的 `player/probe.rs` 使用随应用携带的 libmpv 读取源视频和当前视频，精确 seek 后等待解码事件，再通过 `screenshot-raw video rgba` 复制画面。无需系统 FFmpeg，不操作播放实例。
- 粗索引用采样画面的灰度网格与对比度特征，统计时间偏移候选。过滤黑屏等低信息帧，要求至少三个相符画面及足够区间覆盖，再以约 0.25 秒步长校验重叠区间的开头附近、中段、结尾附近。
- 每段首 / 中 / 尾的偏移差不得超过用户设置的容差（默认 0.5 秒）。界面显示证据类型、得分、锚点偏移差及总覆盖率；证据得分不是统计校准后的成功概率，锚点偏移差不代表剪辑边界精度。重复画面的多个相近候选会拒绝自动采用。
- 自动匹配最长三小时，每次任务可设 30～3600 秒预算。支持保持顺序的多次删减 / 插入，以及有连续声音证据的局部重绘；换序、复杂变速、大幅裁剪、重复长镜头仍可能需要手动调整。缺失证据的片段保留空白或标记待确认。
- 磁力视频分析使用当前已选文件的只读 HTTP 流，会请求需要的分片，可能增加等待和磁盘/网络读取。停止、切集、退出、手动取消都会撤销任务；独立解码器释放后才允许下一任务。

## 本地存储与显示

`app_data_dir()/danmaku/<media-key-md5>.json` 保存 schema 1 项目（源弹幕、区间、混合结果）；同名 `.xml` 是完整输出。键来自规范化本地路径，或 `torrent://<info-hash>/<index>`；摘要仅用于文件名。文件通过临时文件写入和原子替换保存。主数据库 schema 2 不变。

异步请求绑定一次播放的 session ID。相同视频重新打开也得到新 ID；旧任务无法写到当前 UI。切换视频撤销分析令牌，启动仍只读取本地文件。

独立 Canvas 叠层支持普通滚动、反向滚动、顶部和底部弹幕；高级、代码等模式跳过并报告数量。根据 libmpv 采样的时间戳、暂停/缓冲状态和倍速计算位置，seek 后从确定性排布恢复，停止和换集清除。画面纵横比限定显示区域。轨道碰撞时降低屏幕密度，完整文件不删减；不占用或修改现有字幕轨。

真实 libmpv 受控样本：30 秒原视频截取 5–25 秒并缩至一半分辨率，识别源 0–20 秒 → 当前 5–25 秒，首尾偏移差 0 秒。公开 BV 样本的 metadata、1,363 条普通弹幕和远端首/中/尾三帧解码通过；此计数只代表当次可访问弹幕池，不是全部历史弹幕。公网接口会随服务端限制变化。

签名后的 macOS Debug 应用使用独立 bundle ID 和 `BILI_DM_TEST_ROOT` 完成原生验证，正式用户库未参与测试：

- 一批 BV 号与完整视频链接解析为两套弹幕；重启、重新打开视频后从本地恢复源。
- 从原视频裁取 30–50 秒的实际 20 秒片段，自动识别为源 29.98–49.98 秒 → 当前 0–20 秒，相似度 92%，首尾时差 0 秒。
- 在界面将自动结果调整到 30–50 秒，再添加第二个源的手动区间，生成并实际播放 218 条混合弹幕。
- 系统对话框导出 XML，解析确认 218 条、时间有序且全部落在 20 秒视频内，字节内容与已保存结果一致。
- 暂停、跳回中段、开关弹幕、全屏/退出、停止清除通过。全屏中外挂 SRT 与 Canvas 弹幕同时可见，字幕轨未被替换。
- 实测发现 B 站主 CDN 地址可能变化，已增加受支持备用 CDN 地址选择，并加入回归测试。

以上为 macOS arm64、公网公开 BV 与本地文件的证据。磁力分析的流读取和撤销由传输/状态机测试覆盖；尚未使用真实公网 BT 视频复验弹幕画面匹配，也未验证 Windows/Linux、高级弹幕或实际会员账号的完整取流。

## 本机账号与智能搜索

“B 站账号”提供扫码、取消、验证登录、退出并清除凭据。二维码只在内存中保留；扫码成功后以 nav 返回的真实账号为准。Cookie 和账号摘要保存于 `app_data_dir()/account/bilibili.json`，不依赖 Keychain。只有 `api.bilibili.com` 和 `passport.bilibili.com` 的 HTTPS 请求可以附带账号 Cookie；请求不自动跟随跳转，CDN 不携带登录凭据。响应错误不输出 Cookie、登录密钥和带签名视频地址。启动只读取本地摘要，显示“待验证”，不会自动登录或搜索。

二维码生成地址可能返回 `account.bilibili.com` 或 `passport.bilibili.com` 的扫码页面，均限制为 HTTPS。退出清除本地会话并取消正在执行的弹幕任务。需要登录、无观看权益、只有预览或地区限制不等于网络故障；界面展示相应失败原因。尚未实现自动续期，过期后重新扫码。

搜索框从当前文件名提取标题，清理编码/清晰度等标签并保留季集信息，用户可修改。搜索普通投稿、番剧及影视，展开到具体分 P / 集数，以其元数据时长过滤。番剧优先按请求集数排序/筛选。每页最多检查 1～50 个候选，超过上限会提示，支持下一页；搜索排序仅决定尝试顺序，不能作为匹配证据。先匹配画面/声音，再拉取有匹配区间的弹幕，候选之间独立报告失败。

策略可以持久化到本机界面设置：

- 最低时长比例：默认 100%；兼容删减预设为 85%，可调到 0～100%。这是搜索筛选条件，手动添加来源不受影响。
- 最低目标覆盖率：默认 80%，可调到 10～100%；不足时保留结果但全部默认为待确认。
- 匹配依据：音画结合 / 仅画面 / 仅音频。
- 允许删减与允许音频补充重绘分别设置；未启用删减时只接受同一时间偏移的有序链。
- 最短可信段默认 4 秒、锚点偏移容差默认 0.5 秒、画面采样间隔默认 2 秒。
- 分析音轨默认跟随当前所选轨道，也可指定；不改变播放器音量、倍速或声音延迟。
- 单次分析预算默认 600 秒；达到预算或用户取消都会撤销媒体读取，等待独立解码器释放后再开放新任务。

## 音画分段匹配

现有画面指纹负责定位候选锚点，按时间顺序构造允许缺口的匹配链，精查每个区间的首 / 中 / 尾。音频由独立 libmpv 实例解码为临时 11025 Hz 单声道 PCM；按块生成频谱峰值对指纹，全程本机处理，不调用音频识别服务或录制系统输出。PCM 临时目录在分析结束或取消时释放，内存不加载整段 PCM。高频重复特征和低信息音频不作为可靠锚点。

音频锚点以约 0.5 秒窗口聚合并验证连续偏移，剪辑使偏移变化时拆成多段。声音也用于缩小画面验证位置；音频给出位置后仍需实际解码画面校验，不能把“音频匹配”直接标成“音画一致”。局部重绘只有在前后视觉证据支持相同映射时才默认启用。整段仅有音频证据默认未启用，用户可逐段确认或显式允许自动采用。

有足够长且一致的画面/声音重叠时，可以校准不超过 2 秒的固定音画延迟，并对音频区间边界留出余量；局部冲突、不同偏移和目标区间反序保持待确认。没有实现复杂变速、变调或剪辑换序的自动对齐。界面的证据得分不是统计意义上的成功概率；锚点时间误差也不代表所有剪辑边界的精确度。

每段保存证据类型与待确认标记，旧 schema 1 项目缺少这些字段时使用默认值。时间轴可拖动起止边界、按当前播放位置拆分，数字输入支持精调；“对照预览”通过独立解码器显示 B 站来源和当前视频对应时间的静态画面，不改变主播放实例。生成混合文件仍需用户执行，避免自动结果覆盖正在使用的弹幕。

`npm run check`（TypeScript、Rust 格式、全目标 Clippy）、42 个 Rust 测试、4 个前端测试通过。

原生 libmpv 受控样本：60 秒原视频，删除 18～22 秒和 40～43 秒，将剩余视频的 25～33 秒画面替换为纯蓝色，同时降分辨率并重编码 AAC。识别出约 0 / 3.99 / 6.97 秒偏移，目标覆盖约 87.6%；生成五段，其中重绘段由音频支撑，其余段经音画验证。未将删除部分线性拉伸填满。仅画面模式会留下无法确认的重绘缺口。

公网验证：扫码二维码生成和 waiting 状态轮询；标题搜索返回普通视频、番剧和影视类别；PGC 剧集 CID/时长及公开可观看单集的完整视频/音频流解析。未使用真实会员账号扫码，因此“扫码确认后的会员权益取流”仍需真实账号验收；本地会话保存/恢复/清除已有自动测试。真实公网 BT 的音画匹配和 Windows/Linux 未复验。
