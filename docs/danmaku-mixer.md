# 哔哩哔哩弹幕混合

日期：2026-10-04。在当前内嵌 libmpv 播放器上增加独立的弹幕解析、画面匹配、区间混合与显示功能。

## 使用

1. 先打开本地视频或播放选中的磁力视频，等待播放器读取时长。
2. 打开右侧“混合弹幕”，每行粘贴一个 BV 号、Bilibili 视频链接或 b23.tv 短链接，点击批量解析。不带 `?p=` 的视频读取全部分 P，带该参数只读取指定分 P。
3. 勾选弹幕源并智能匹配，或点击某个源的“手动添加区间”。同一源可以添加多个不连续区间，多个源可以覆盖同一目标区间，也可以拼接覆盖完整视频。
4. 编辑“源开始 / 源结束 / 当前开始 / 当前结束”。单位为秒、支持小数。可以定位目标开始位置，或用当前播放进度设置目标起点。
5. 点击“生成混合文件并播放”。Rust 校验边界和时长；未经生成的编辑不会替换上次已应用的弹幕。
6. 可以开关弹幕、调整字号和透明度，或通过系统保存对话框导出标准 XML。重开同一视频自动读取本地已生成项目，不触发 B 站请求。

## 时间映射

区间为半开区间 `[sourceStart, sourceEnd)`，避免相邻截取区间重复纳入边界弹幕。映射公式：

```text
targetTime = targetStart + (sourceTime - sourceStart)
             × (targetEnd - targetStart) / (sourceEnd - sourceStart)
```

所有时间必须有限、非负且位于各自视频时长内。时长比例允许 0.25～4，非等时长显示同步提示。相同来源、相同弹幕 ID、相同映射毫秒的记录去重；不同来源/用户的相同文字仍保留。结果按目标时间排序，超出当前视频的弹幕不会输出；未覆盖的视频区间有明确提示。

## 解析与匹配

- `bilibili.rs` 读取 `view` 的 BV/CID/分 P/时长，按每 360 秒读取 `seg.so` protobuf 分段。分段失败使该弹幕源本次解析失败，不把半套弹幕标成成功；批次内其余源可以成功。每批 20 个输入，每项目 50 个分 P、20 万条弹幕，最长手动视频 24 小时。
- 视频流在匹配时取得，优先低带宽 AVC DASH，无须音频；普通 playurl 失败时尝试 WBI 接口。拒绝明显不符的预览时长。CDN URL 不写入项目，不读取浏览器 Cookie，不登录或绕过权限。旧版多段 durl、番剧 ep/ss、直播尚不支持。
- 独立的 `player/probe.rs` 使用随应用携带的 libmpv 读取源视频和当前视频，精确 seek 后等待解码事件，再通过 `screenshot-raw video rgba` 复制画面。无需系统 FFmpeg，不操作播放实例。
- 粗索引用采样画面的灰度网格与对比度特征，统计时间偏移候选。过滤黑屏等低信息帧，要求至少三个相符画面及足够区间覆盖，再以约 0.25 秒步长校验重叠区间的开头附近、中段、结尾附近。
- 首尾时间偏移差及中段偏移差不得超过 0.85 秒。界面显示相似度、首尾得分、时差，结果仍需预览确认；相似度不是统计校准后的成功概率。重复画面的多个相近候选会拒绝自动采用。
- 自动匹配当前限制单个源和目标均在两小时以内；每个源生成一个主要连续重叠区间。内部多次删减、换序、变速、长黑场、画中画或大面积裁剪需要手动拆段。首尾附近取样避开极短黑场，并不承诺每个剪辑都能自动识别。
- 磁力视频分析使用当前已选文件的只读 HTTP 流，会请求需要的分片，可能增加等待和磁盘/网络读取。停止、切集、退出、手动取消都会撤销任务；独立解码器释放后才允许下一任务。

## 本地存储与显示

`app_data_dir()/danmaku/<media-key-md5>.json` 保存 schema 1 项目（源弹幕、区间、混合结果）；同名 `.xml` 是完整输出。键来自规范化本地路径，或 `torrent://<info-hash>/<index>`；摘要仅用于文件名。文件通过临时文件写入和原子替换保存。主数据库 schema 2 不变。

异步请求绑定一次播放的 session ID。相同视频重新打开也得到新 ID；旧任务无法写到当前 UI。切换视频撤销分析令牌，启动仍只读取本地文件。

独立 Canvas 叠层支持普通滚动、反向滚动、顶部和底部弹幕；高级、代码等模式跳过并报告数量。根据 libmpv 采样的时间戳、暂停/缓冲状态和倍速计算位置，seek 后从确定性排布恢复，停止和换集清除。画面纵横比限定显示区域。轨道碰撞时降低屏幕密度，完整文件不删减；不占用或修改现有字幕轨。

## 验证

```sh
npm run typecheck
npm test
npm run rust:test
npm run rust:fmt
npm run rust:clippy
cargo run --manifest-path src-tauri/Cargo.toml --example danmaku_smoke -- <target.mp4> <source.mp4>
cargo run --manifest-path src-tauri/Cargo.toml --example danmaku_smoke -- BV1GJ411x7h7
```

自动测试覆盖 BV/URL/分 P、protobuf/错误响应、跨源合并、半开边界、重复映射、缩放、无效参数、XML 转义、空白/无关画面拒绝、首尾时间不一致拒绝、存储重读、批次部分失败、会话隔离、停止取消、并发排他，以及前端播放时钟、反向/固定弹幕和碰撞排布。

32 个 Rust 测试、3 个前端测试，以及 TypeScript、rustfmt、Clippy `-D warnings` 均通过。

真实 libmpv 受控样本：30 秒原视频截取 5–25 秒并缩至一半分辨率，识别源 0–20 秒 → 当前 5–25 秒，首尾偏移差 0 秒。公开 BV 样本的 metadata、1,363 条普通弹幕和远端首/中/尾三帧解码通过；此计数只代表当次可访问弹幕池，不是全部历史弹幕。公网接口会随服务端限制变化。

签名后的 macOS Debug 应用使用独立 bundle ID 和 `BILI_DM_TEST_ROOT` 完成原生验证，正式用户库未参与测试：

- 一批 BV 号与完整视频链接解析为两套弹幕；重启、重新打开视频后从本地恢复源。
- 从原视频裁取 30–50 秒的实际 20 秒片段，自动识别为源 29.98–49.98 秒 → 当前 0–20 秒，相似度 92%，首尾时差 0 秒。
- 在界面将自动结果调整到 30–50 秒，再添加第二个源的手动区间，生成并实际播放 218 条混合弹幕。
- 系统对话框导出 XML，解析确认 218 条、时间有序且全部落在 20 秒视频内，字节内容与已保存结果一致。
- 暂停、跳回中段、开关弹幕、全屏/退出、停止清除通过。全屏中外挂 SRT 与 Canvas 弹幕同时可见，字幕轨未被替换。
- 实测发现 B 站主 CDN 地址可能变化，已增加受支持备用 CDN 地址选择，并加入回归测试。

以上为 macOS arm64、公网公开 BV 与本地文件的证据。磁力分析的流读取和撤销由传输/状态机测试覆盖；尚未使用真实公网 BT 视频复验弹幕画面匹配，也未验证 Windows/Linux、高级弹幕或需要登录的视频。
